Breaking Change: each surface reads its own locale. `/api` reads `?locale=`, the panel reads `?locale=` then its `rime.locale` cookie, and the site reads the route param named `locale`. A code the config does not list is skipped: the next place the surface reads is tried, the panel's cookie after an unknown `?locale=`, and the default locale when none is left. The cookie is written for the panel's path only, once a locale switch goes ahead, so the site and `/api` do not follow the panel's locale; it is `Secure` on https only, so a panel served over plain http keeps its locale. A panel save names the locale of the row on screen, so a cancelled switch, another tab or the live editor cannot move it. A site route names its locale `[[locale=locale]]`: rime generates the `locale` matcher, which types `params.locale` and leaves a segment that is not a locale to the next route. A site that keeps its locale elsewhere sets it with `rime.setLocale()`, which sets the default locale for a code the config does not list. A REST body carrying `locale` answers 400: name the locale with `?locale=`. `rime.getLocale()` is removed: read `event.locals.locale`. A duplicate or a locale copy leaves the request's locale alone: a hook reads the locale it writes in from `context.params.locale`. A read with `depth` resolves its relations and links in its own locale: `find({ locale: 'en', depth: 1 })` reads the related documents in `en` whatever the request's locale. The live preview reads related documents in the edited document's locale, and `Relation.resolve(value, { locale })` reads them in the locale given (the default locale without one). In the panel, the relation fields read their documents in the panel's locale, and a block's focus render receives `locale` beside `block`, `path`, `fields` and `form`: it reads a relation with `Relation.resolve(block.image, { locale })`.
